# perdanakun.com

The source code behind my personal portfolio — [perdanakun.com](https://www.perdanakun.com).

I'm a **UI Designer with a background in iconography and design systems**, and this project is part of my exploration into **UX, front-end development, and design engineering**.

I've spent most of my career working with visual design — icons, illustrations, interfaces, and visual systems.

Now I'm interested in going one layer deeper:

**What happens when I don't stop at designing the interface, but also build the system behind it?**

That's what this project is about.

## The Idea

I didn't want to build another portfolio that looks like a portfolio.

Most personal websites follow a familiar pattern:

```text
Landing page
↓
Scroll
↓
Projects
↓
Scroll
↓
About
↓
Scroll
↓
Contact
```

So I tried something different.

I turned my portfolio into a small **personal computer**.

```text
Desktop
│
├── About
├── Projects
├── CV
├── Contact
├── AI Messenger
└── Experiments
```

Information is presented through windows, folders, files, icons, and applications.

The interface is inspired by the desktop environments I grew up with, particularly the visual language of Windows 95/98 and the feeling of using an old personal computer.

It's nostalgic, but the reason I chose this metaphor is more practical:

**desktop interfaces already give people a familiar mental model for navigating information.**

You open something.

You move between windows.

You minimize it.

You find it again in the taskbar.

I wanted to see if that familiar interaction model could work as a portfolio.

## Designing in Code

One thing I wanted to change from my usual design workflow was the relationship between design and implementation.

Instead of:

```text
Design
↓
Figma
↓
Prototype
↓
Handoff
↓
Code
```

I experimented with:

```text
Idea
↓
UX
↓
Interaction
↓
Component
↓
Code
↓
Browser
↓
Try it
↓
Change it
```

The browser becomes part of the design process.

A window isn't just something that looks like a window.

It needs to know how to:

* Open
* Close
* Minimize
* Restore
* Move
* Respond to different screen sizes
* Maintain its state

The same goes for desktop icons, folders, buttons, dialogs, and the taskbar.

That's where this project gets interesting for me.

Some of the things I've been working with:

The interesting part is adapting that visual language into something that actually works as my own interface.

## AI Messenger

There's also an AI assistant inside the portfolio.

The idea is simple:

Instead of asking visitors to dig through my CV, experience, and portfolio to find basic information, they can just ask.

For example:

> "What does Perdana do?"

> "What's his background?"

> "What kind of design work has he done?"

> "What is he currently exploring?"

I think this is an interesting direction for personal websites because the way people look for information is changing.

Sometimes people don't want to browse.

They just want to ask.

So I experimented with making an AI assistant act as a conversational layer on top of my portfolio.

## A Few Things I've Built

The project has evolved through small experiments and problems rather than being designed completely upfront.

Some of the things I've worked through:

* Centralized window management
* Minimize / restore behavior
* Desktop icon interactions
* Double-click interactions
* Mobile double-tap interactions
* Responsive application windows
* Touch interaction
* Contact form validation
* Custom alert windows
* AI Messenger
* Taskbar integration
* Image viewer behavior
* Sound effects
* Cross-device interaction

A lot of these started as simple visual problems.

Then I had to figure out what needed to happen underneath.

That has probably been the most useful part of building this.

## This Is Still an Experiment

I'm not presenting this repository as an example of perfect engineering.

I'm a designer exploring code.

There are things here that will probably change, get refactored, or turn out to be better solved another way.

That's intentional.

I'm interested in learning what happens when a designer gets involved not only in **how an interface looks**, but also in **how the system behaves**.

For me, that's the direction toward design engineering.
