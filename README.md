## About the Project

This project started with a simple question:

> **What if a portfolio wasn't something to scroll through, but a space to explore?**

Most portfolios follow a familiar pattern — scroll down, read, view the work, move on.

I wanted to try something different.

Instead of presenting my work as a collection of pages, I designed the portfolio as a **personal desktop environment**: windows, folders, applications, and files that you can explore in your own way.

There's no single path through it. You can open what interests you, move around, and discover things along the way.

Rather than only showing what I've made, I wanted the **experience itself** to give a little sense of **how I think and work**.

---

## Designing in Code

My background is in **visual design**, **iconography**, **illustration**, and **visual systems**. Lately, I've been exploring what happens when I take that foundation into the browser and start **designing with code**.

This project is part of that exploration.

Building directly in **React** lets me work through things that don't really exist in a static design file — **interaction states**, **responsive behaviour**, **technical constraints**, **component systems**, and all the small details that appear once something actually works.

I'm still learning the engineering side of it. For me, that's part of the process.

## A Portfolio Treated as a Product

I don't see this as a finished website.

I'm treating it more like a **small product** that happens to be my portfolio.

It has its own **information architecture**, **interaction model**, **visual system**, **components**, **constraints**, and **lifecycle**. And like any product, there are things to improve, rethink, break, and rebuild.

As my practice develops, the portfolio develops with it — through new interactions, new content, and new ways of presenting the work.

So this is an **ongoing project**, not a final version.
